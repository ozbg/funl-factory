The path

Five steps. You sign three things; the factory does the rest and asks only when it must.

Run Define (/north-star, /mockup, /to-board) in the app's folder, or in an empty folder to test an idea. /to-board --dry-run writes the spec and shows the cards without touching a board.

Stages

What goes in, what comes out, and who does the work.

1 · Define the destination

/north-star you answer

  • ≤ 3 questions a round, 12 at most
  • Must list: 3 for a prototype, 5 for a product
  • Ends with the postcard and a blind test you score 1–5
  • Out: docs/shape/north-star.md, later.md, a log line
2 · Feel it

/mockup you click

  • One HTML file, fake data, one tab per core-loop step
  • 2–3 radically different versions; you pick one
  • At most 2 tweak rounds, then the postcard question
  • Out: docs/shape/mockup.html, a Mock-up: line on the north star
3 · Plan the route

/to-board factory decides

  • One-page spec: postcard, must-haves, must-nevers as invariants, contracts
  • Cards Haiku can build without guessing; foundation first, Demo last
  • Blind reviewer + a Haiku read of every card, one fix round
  • You see the table and the verdict, and change scope only
  • Out: spec.md, coverage.md, draft zones.yaml, cards in Ready
4 · Build

/super-board lint then run factory

  • Lint checks Ready cards and coverage
  • Each wave: build, QA, review and merge through the gate
  • A digest on a merge, breach or ask; nothing else interrupts you
  • status any time; stop to halt cleanly
5 · Score it

/super-board report you read

  • Define, Build, Cost, Done, each against a target
  • --log adds the app to the factory log
  • --compare shows every app side by side
Any time · Keep it healthy

/super-collect factory

  • Pulls problems from Sentry, PostHog, GitHub, merged PRs, architecture
  • Each one checked by a fresh verifier
  • Verified findings go to Backlog in the card format

The board

Seven columns. One card is one worktree, one branch, one PR.

ColumnHow a card gets hereWhat happens
Backlogsuper-collect findings, splits, refused cardsWaits. Not part of a run until you move it to Ready.
Ready/to-board after your scope reviewLint checks it. The planner admits it if it has ACs, a must-have and no file clash.
BuildingA wave picks it upIts own worktree. Test first, smallest change, draft PR.

ReviewAfter QA, or straight from Build for greenOpus reviews, then the merge gate re-proves the branch and merges.
BlockedRound cap hit, or a step only you can do (🙋)Last comment line says blocked-by: and what's needed.
DoneMerged through the gateCounts towards its must-have in coverage.md.

Zones

Every file sits in a zone (docs/agents/zones.yaml). A card takes the highest zone of any file it touches. The zone sets how hard it's checked.

ZoneWhat lives thereChecksRoundsBuilder
greenScreens, read-only views, copyTypecheck, tests, light review. No QA lane.1Haiku
amberFeatures that change data through the red write pathEvery AC tested, the zone's bar, scenario run, review2Haiku
redAnything that can lose, leak or corrupt data, or give the agent rights only you haveInvariant suite, mutation test, security pass, adversarial review3Sonnet

A bounce must cite something: AC2, an invariant I4, a bar: line, or a bug: with repro steps. No citation, no bounce: it becomes a note.

Each level is done only when the level below it is. Three of the four are checked by scripts.

Your calls

You set direction, scope and business rules. The factory makes technical calls: stack, data model, card cuts, review depth, test seams. If it asks you about those, that's a bug in the skill.

YouWhen
Say yes to the postcardEnd of /north-star and /mockup
Score the blind test 1–5End of /north-star
Approve the card list for scope/to-board, once
Sign zones.yamlBefore the first run, and when an area is promoted
Merge money, auth and destructive-schema PRs; run anything on a live databaseA 🙋 card in Blocked
Keep going, raise the budget, or stopBudget breach in the digest
Re-read the north star next morningThe day after signing

Skills

Installed into every app. The board runs some of them for you; type the rest.

You type

SkillUse it when
/north-starA new app, or a rescope. Add --panel for a product lead, architect and scope cutter behind the questions.
/mockupRight after the north star is signed, to feel the core loop.
/to-boardAfter the mock-up. Also after a north-star change (it rescopes). --dry-run to test.
/super-boardonboard to set up or repair · lint before a run · run · status · stop · report
/super-collectAfter real use: turn errors, rage clicks and repeated PR fixes into Backlog cards.
/git-syncCommit, pull and push the current branch. Never force pushes.

The board runs these

SkillWhat it does
/super-buildBuilder lane: one card in its own worktree, test first, draft PR. Never merges.
/super-qaTester lane: proves each AC by zone. Standalone: /super-qa <url> bug-bashes a live site.
/super-reviewReviewer lane: forms its own view first, bounces only on a cited blocker, merges through the gate.
/pr-security-reviewSecurity pass on red and boundary amber cards. A finding fails QA.
